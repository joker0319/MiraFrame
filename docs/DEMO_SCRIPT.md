# 2 分钟演示录制脚本

目标：让没看过项目的人在两分钟内看懂「这是一条可观察、可打断、可反馈的 Agent 创作流水线」，而不是一堆生成结果的幻灯片。

## 已录制素材（2026-11-25）

用真实项目 23《纸鸢引》（`completed`）通过浏览器 CDP 逐节点截图，合成了 18 秒无旁白巡览视频 `docs/demo.mp4`，并产出五张截图：

| 文件 | 对应节点 | 状态 |
| ---- | -------- | ---- |
| `demo-workflow.jpg` | 五节点流水线总览 | 已有 |
| `demo-characters.jpg` | 角色设定（3 张真实角色图） | 已有 |
| `demo-shots.jpg` | 分镜脚本（6 镜） | 已有 |
| `demo-frames.jpg` | 镜头画面（6/6 视频） | 已有 |
| `demo-export.jpg` | 合成输出（成片播放器 + 导出按钮） | 已有 |

**尚缺三张**：`demo-repair.jpg`（一致性漂移红点 + 自动修复汇总）、`demo-critique.jpg`（两阶段评分并存）、`demo-subtitle.jpg`（灯箱字幕开关）。原因：项目 23 已全部完成，无漂移可展示，评分卡与字幕灯箱也未在截图时展开。补录时需用一个进行中的项目，或在该项目上手动展开对应面板后单独截屏。下面的分镜表仍是完整目标版本。

录制前先确认：

- 应用已经按 README「快速开始」跑起来，浏览器开在 1440×900 左右、缩放 125%，窗口里不要出现存有密钥的终端或 `.env`。
- 最好准备一个**已经生成到「合成输出」阶段的项目**，再留一个可以重新触发的节点。演示的是工作流和反馈闭环，不是等模型出图。
- 如果只能用 fake provider，占位图会让「一致性修复」「视觉审查」看起来很假；这两段建议用真实 provider 的既有结果，或者提前截好图。

## 剪辑提示

- 每段之间硬切，不要转场；停顿处用「等生成」的画面带过，不要留黑屏。
- 鼠标移动慢一点，点击前停半秒，让人看清按钮文字。
- 提到「不信口开河」的地方（字幕不进 mp4、视觉审查不复审视频）要停在对应 UI 上说，别只靠旁白。
- 成片控制在 2 分钟左右；超过 3 分钟就砍掉项目列表那一段，直接从工作台开始。
